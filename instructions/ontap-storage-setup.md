# ONTAP Storage Setup

The launch form does not show run or skip switches. Leave a section blank and that task stays skipped. Enter values and that task runs. The FIPS dropdown is the exception: it defaults to false and that task runs on every launch.

Ending the deployment runs a teardown for each task that has one, in reverse dependency order, so SVM items are removed before the SVM, and the SVM before the aggregates, IPspace, and interface groups. The End section at the end of this document lists what each teardown does. Tasks that run on every launch have no teardown: pre-validation, cluster-management auto-revert, spare-disk zeroing, the default broadcast-domain cleanup, cluster HA, CDP, LLDP, and storage failover. FIPS also runs on every launch. It has a teardown only when the dropdown is true, and that teardown sets FIPS back to false. Licenses, flow control, HTTP cluster management, disk-class discovery, post-config validation, and the vsadmin password have no teardown. The vsadmin password is removed when the SVM is deleted. Spare-disk zeroing cannot be reversed.

Required fields are the agent, cluster management address, and password. The username defaults to admin. You can click Next and Finish with only those filled in.

Storage failover, cluster HA, cluster-management auto-revert, spare-disk zeroing, CDP, LLDP, and default broadcast-domain cleanup do not have their own fields. Every launch discovers the cluster nodes, enables storage failover on each node, and sets cluster HA only when that discovery finds exactly two nodes. It also finds the cluster management interface and enables auto-revert on it, zeros spare disks, and enables CDP and LLDP. It deletes an autogenerated Default broadcast domain when that domain is in the Default IPspace, its name starts with `Default-`, and it contains no cluster or node-management port. That cleanup runs before the interface group is created. Creating the interface group makes ONTAP add domains such as `Default-1` in the Default IPspace with the interface group as a member. Post-config validation deletes those: a domain is deleted when its name starts with `Default-`, it is in the Default IPspace, and one of its ports is the interface group. The domain named `Default` is left in place. A blank interface group name skips that delete. End leaves auto-revert, spare-disk zeroing, cluster HA, storage failover, CDP, LLDP, and that broadcast-domain cleanup in place.

Node configuration is one table. Each row is one node, so the node name is entered once. That row has separate columns for the service-processor address, data ports, aggregate name, and disk count. One aggregate is created on that node. To skip the service-processor, aggregate, interface-group, and data-port tasks, delete every row. A blank row still counts as a row, and Finish stays disabled until that row is filled in or deleted. Those same rows are the nodes used for VLANs. A VLAN is created on a node when that row lists data ports, because that is where the interface group exists. The aggregate name on each row is also assigned to the SVM when an SVM name is set.

Network Configuration holds the interface group name and mode, and the IPspace name. The interface group name defaults to `a0a`. You can change it. The mode defaults to `multimode_lacp`. The dropdown also offers `multimode` and `singlemode`. Each node that lists data ports gets that interface group, those ports are added to it, and the group MTU is set to 9000. Traffic is distributed by port. The same name and mode are used on every node. The mode is applied when the group is created. Clear the name to skip only the interface group. A blank IPspace name does not skip it. The other node-configuration tasks still run.

That same section also holds the VLAN name and VLAN ID for in-band management, NFS, iSCSI fabric A, and iSCSI fabric B. In-band management is the management VLAN. NFS is storage protocol NFS. iSCSI-A is storage protocol iSCSI on fabric A, and iSCSI-B is storage protocol iSCSI on fabric B. Leave the IPspace name blank to skip IPspace, broadcast domain, and VLAN creation. The interface group task still runs from its own name and the node data ports. The IPspace task does not wait for the interface group. An IPspace name on its own creates that IPspace. The broadcast-domain task runs after the IPspace task. It creates a broadcast domain for each network whose VLAN name is set, and it does not read the VLAN ID. Leave a VLAN name blank to skip that broadcast domain. A VLAN name problem does not fail the IPspace task. When the interface group name is set, a node row lists data ports, and that network also has a VLAN ID, the VLAN interface task creates that VLAN on the interface group and adds it to the broadcast domain. That task runs after the broadcast domains and the interface group. The VLAN ID, the interface group name, and the node names are checked there. Leave a VLAN ID blank to skip that VLAN interface. The broadcast domain is still created. ONTAP names the interface `<interface group>-<VLAN ID>`, for example `a0a-1022`. In-band management uses MTU 1500. NFS and both iSCSI VLANs use MTU 9000. A blank interface group name, or node rows with no data ports, skips the VLAN interfaces. The broadcast domains for the filled-in networks are still created.

SVM Configuration creates one SVM. Enter the SVM name to run it. Leave that name blank and the SVM task stays skipped, along with the load-sharing SnapMirror, vsadmin, the SVM login banner, the management LIF, the default route, SVM DNS, the NFS export policy rule, and the audit log volume. The SVM is created in the IPspace from Network Configuration, so that name has to be filled in. The SVM task waits for the IPspace and the aggregates. It does not wait for the VLAN interfaces. The aggregate names from the node configuration rows are assigned to the SVM, so those rows need at least one aggregate name. The protocol dropdown lists nfs and iscsi and starts with nothing selected. Choose nfs, iscsi, or both. The SVM task waits for the license task when legacy keys or an NLF are entered. It looks up each selected license package first. The run shows the package, owner, serial number, installed license, expiration, and licenses.compliance.state. It continues only when every serial for that package is compliant. nfs starts the NFS service with NFSv3 and NFSv4.1 enabled and UDP disabled. iscsi starts the iSCSI service. Those steps are part of the SVM task.

The load-sharing SnapMirror of the SVM root volume is its own task. It runs after the SVM task when the SVM name and the job name or job minutes are set. It creates the mirror volumes, then the job schedule, then the SnapMirror relationship. Both the job name and the job minutes are required. The schedule name defaults to `15min` and the minutes default to `0,15,30,45`, which runs at minute 0, 15, 30, and 45 of every hour. Other 15-minute examples are `5,20,35,50` and `7,22,37,52`. Clear both the job name and the minutes to skip the mirror volumes, the schedule, and the SnapMirror relationship. Set only one and this task fails at the schedule, after the mirror volumes are created. An invalid job name or invalid job minutes fail this task the same way. The SVM task is already done, so vsadmin, the banner, the management LIF, the route, SVM DNS, the NFS export policy, and the audit log volume still run. This task reads the node that hosts the SVM root volume from the cluster. Every node row that names an aggregate needs a node name, each node can appear only once, and one of those rows must be the root volume's node. Mirrors are 1 GB data-protection volumes, created on the aggregates from the node rows that are not on that same node. The SnapMirror relationship is load-sharing, initialized, and uses the job schedule. When every aggregate from the node rows is already on the root volume's node, the mirrors and the relationship are skipped. The schedule is still created when its fields are filled in.

The vsadmin password is its own task. It runs after the SVM task. When the password is filled in, it is set on vsadmin and the account is unlocked for http, ontapi, and ssh. Leave it blank to skip that task and leave vsadmin unchanged. The SVM login banner is its own task and runs after the SVM task. It is set when that text is filled in. Leave it blank to skip the banner. When the SVM stays, End clears the banner if the SVM still shows the text from the form.

SVM management LIF is its own task. It runs after the SVM task and the VLAN interface task. It is four fields: `svm_mgmt_lif_name`, `svm_mgmt_lif_address`, `svm_mgmt_lif_netmask`, and `svm_mgmt_lif_gateway`. One SVM has one management LIF, so there is no control to add another. Example: `svm_mgmt_lif_name` `svm-mgmt`, `svm_mgmt_lif_address` `10.102.2.50`, `svm_mgmt_lif_netmask` `255.255.255.0`, `svm_mgmt_lif_gateway` `10.102.2.254`. Leave `svm_mgmt_lif_name`, `svm_mgmt_lif_address`, or `svm_mgmt_lif_netmask` blank to skip the LIF. Leave the interface group name or the in-band management VLAN name or VLAN ID blank to skip it as well. Leave `svm_mgmt_lif_gateway` blank to skip the default route. If the LIF is skipped, the route is skipped as well. The LIF is created when `svm_mgmt_lif_name`, `svm_mgmt_lif_address`, and `svm_mgmt_lif_netmask` are all filled in and the interface group and in-band management VLAN are filled in. At least one node row must list data ports. The interface group and the VLAN interface are created only on those nodes, so with no data ports both of those tasks finish without creating the home port. The LIF task then fails before it calls the cluster. Add data ports to a node row, or clear the LIF fields to skip it. Leave the SVM name blank and the LIF, the default route, and SVM DNS are skipped with the SVM task.

The LIF task reads the node that hosts the SVM root volume from the cluster: the root volume is found, its aggregate is read, and the aggregate reports the node. The home port is not entered on the form. It is the in-band management VLAN interface from Network Configuration. The interface group name and the in-band management VLAN ID are joined with a hyphen. Interface group `a0a` and VLAN ID `2235` make home port `a0a-2235`. The VLAN name has to be filled in as well, because that is what creates the VLAN interface. If the interface group name, the VLAN name, or the VLAN ID is blank, LIF creation is skipped. The LIF uses service policy `default-management`, admin status up, failover policy `broadcast-domain-wide`, and auto-revert. The default route is its own task. It runs after the LIF task. When `svm_mgmt_lif_gateway` is filled in and the LIF fields are filled in, that gateway is added as the SVM default route, destination `0.0.0.0/0`. A blank gateway skips the route. If the LIF is skipped, the route is skipped as well.

SVM DNS is its own task. It runs after the default route. The default route runs after the management LIF, and that LIF runs after the SVM task. It is two fields: `svm_dns_servers` and `svm_dns_domain`. `svm_dns_servers` is a comma-separated list of IPv4 addresses, for example `10.1.1.10,10.1.1.11`. `svm_dns_domain` is the DNS domain name, for example `example.com`. These are separate from the cluster DNS domain and DNS servers. Fill in both to configure DNS on the SVM. Leave both blank to skip it. Set only one and the SVM DNS task fails. The SVM task is already done.

Volume Configuration holds the NFS export policy rule and the SVM audit log volume. Leave the SVM name blank and both stay skipped.

The NFS export policy rule is its own task. It runs after the SVM task when the SVM name and `nfs_client_match` are set. `nfs_client_match` is the IPv4 subnet for rule index 1 on the SVM default export policy, for example `192.168.52.0/24`. Protocol is nfs. Read-only, read-write, and superuser security are sys, and suid is allowed. Those values are fixed. The same task then assigns export policy default to the SVM root volume, read from the cluster (`is_svm_root`, or `<SVM name>_root` with hyphens replaced by underscores). Leave `nfs_client_match` blank to skip the rule and that assignment. If nfs is not selected, this task fails. The SVM task is already done.

The audit log volume is its own task. It runs after the SVM task when the SVM name is set and any of `audit_log_volume_name`, `audit_log_volume_size_gb`, or `audit_log_aggregate` is set. It creates the FlexVol, refreshes a load-sharing mirror set when one already exists, then creates and enables SVM auditing. All three fields are required. `audit_log_volume_name` is the volume name, for example `audit_log`. `audit_log_volume_size_gb` is the size in gigabytes. Enter the number only, for example `50`. `audit_log_aggregate` is an aggregate name from the node configuration rows, for example `AA02_C800_01_SSD_CAP_1`. The volume is online, uses export policy default, has no space guarantee and no snapshot reserve, and is mounted at `/<volume name>`. Auditing is enabled and the log path is that same junction. The directory has to exist before auditing is enabled, and the path has to be absolute. A SnapMirror relationship is not required. ONTAP updates an existing load-sharing mirror set automatically when this volume is created with a junction path. When a set is already present, this task also runs `snapmirror update-ls-set` so the mirrors refresh before the next schedule. When no set is present, that refresh is skipped and the volume and the audit configuration are still created. Leave all three blank to skip the volume, the mirror refresh, and auditing. Set any of them and leave one blank and this task fails.

Cluster name is used by the location, timezone, and HTTP tasks. It must exactly match the cluster's current name. Entering a different value renames the cluster when location or timezone runs. When the cluster name is filled in, HTTP is removed from the cluster default-management service policy. HTTPS, SSH, and the other services on that policy stay in place. End leaves HTTP removed. Leave the cluster name blank to skip location, timezone, and this HTTP task.

| Filled in | Task that runs |
| --- | --- |
| Cluster name and location | Update cluster location |
| Node configuration rows | Configure each node's service processor, disable flow control on its data ports, discover the disk class, and create one aggregate on that node. Those aggregate names are assigned to the SVM when an SVM name is set. End leaves flow control disabled and does not undo disk-class discovery |
| Interface group name, mode, and data ports | Create that interface group on each node that lists data ports, add those ports, and set the group MTU to 9000. The name defaults to `a0a` and the mode defaults to `multimode_lacp`. Clear the name to skip this task. A blank IPspace name does not skip it |
| IPspace name | Create that IPspace. This task does not wait for the interface group. Leave the IPspace name blank to skip IPspace, broadcast-domain, and VLAN creation. The interface group task still runs |
| IPspace name and a VLAN name | Create that network's broadcast domain after the IPspace task. The VLAN ID is not used. In-band management uses MTU 1500. NFS uses MTU 9000. iSCSI fabric A and iSCSI fabric B each use MTU 9000. Leave that VLAN name blank to skip it. A VLAN name problem does not fail the IPspace task |
| IPspace name, a VLAN name and VLAN ID, the interface group name, and node rows that list data ports | Add that VLAN to the interface group on each of those nodes. This task runs after the broadcast domains and the interface group. Leave the VLAN ID blank to skip the VLAN interface. The broadcast domain is still created. Leave the interface group name blank, or list no data ports, and the VLAN interfaces are skipped |
| SVM name, the IPspace name, at least one aggregate name on the node rows, and nfs, iscsi, or both | Create the SVM in that IPspace, assign those aggregates, and allow the selected protocols. This task waits for the IPspace and the aggregates. It waits for the license task when legacy keys or an NLF are entered. It looks up each selected nfs or iscsi package first, shows the owner, serial number, installed license, expiration, and licenses.compliance.state, and fails if a serial for that package is missing or not compliant. nfs starts NFSv3 and NFSv4.1 and disables UDP. iscsi starts the iSCSI service. Leave the SVM name blank to skip the SVM and the tasks that follow it. The protocol dropdown starts empty; choose nfs, iscsi, or both |
| SVM name, job name, and job minutes | Create the load-sharing SnapMirror of the SVM root volume after the SVM task. Both the job name and the job minutes are required. The schedule defaults to `15min` and `0,15,30,45`. Create a 1 GB load-sharing mirror on each aggregate that is not on the root volume's node, then create the job schedule, then initialize the load-sharing SnapMirror relationship that uses that schedule. Clear both job fields to skip the mirrors, the schedule, and the relationship. Set only one and this task fails at the schedule |
| SVM name and vsadmin password | Set the vsadmin password and unlock vsadmin for http, ontapi, and ssh. This task runs after the SVM task. Leave the password blank to leave vsadmin unchanged |
| SVM name and SVM login banner | Set the SVM login banner after the SVM task. Leave it blank to skip the banner. When the SVM stays, End clears the banner if the SVM still shows the text from the form. |
| SVM name, svm_mgmt_lif_name, svm_mgmt_lif_address, and svm_mgmt_lif_netmask, plus the interface group name, the in-band management VLAN name and VLAN ID, and data ports on a node row | Create the SVM management LIF on the node that hosts the SVM root volume. This task runs after the SVM and the VLAN interfaces. The home port is `<interface group>-<VLAN ID>`, for example `a0a-2235`. Leave svm_mgmt_lif_name, svm_mgmt_lif_address, or svm_mgmt_lif_netmask blank to skip the LIF. Leave the interface group or the in-band management VLAN blank to skip it as well. With no data ports on any node row this task fails before it calls the cluster. Leave the SVM name blank to skip it with the SVM task |
| SVM name, the SVM management LIF fields, and svm_mgmt_lif_gateway | Create the SVM default route `0.0.0.0/0` through that gateway. This task runs after the management LIF. Leave svm_mgmt_lif_gateway blank, or skip the LIF, and the route is skipped. Leave the SVM name blank to skip it with the SVM task |
| SVM name and both svm_dns_servers and svm_dns_domain | Configure DNS on the SVM after the default route. The default route runs after the management LIF, and that LIF runs after the SVM task. Example servers `10.1.1.10,10.1.1.11` and domain `example.com`. Leave both fields blank to skip SVM DNS. Set only one and the SVM DNS task fails. These fields are separate from cluster DNS |
| SVM name and nfs_client_match, with nfs selected | Add rule index 1 to the SVM default export policy for that IPv4 subnet, then assign export policy default to the SVM root volume. Example `192.168.52.0/24`. Protocol is nfs. Read-only, read-write, and superuser security are sys, and suid is allowed. The root volume is read from the cluster (`is_svm_root`, or `<SVM name>_root` with hyphens replaced by underscores). Runs after the SVM task. Leave nfs_client_match blank to skip both. If nfs is not selected, this task fails |
| SVM name and any of audit_log_volume_name, audit_log_volume_size_gb, or audit_log_aggregate | Create the audit log FlexVol, refresh a load-sharing mirror set when one already exists, then enable SVM auditing. This task runs after the SVM task. All three fields are required. The name is the volume name, for example `audit_log`. `audit_log_volume_size_gb` is the size in gigabytes, for example `50`. The aggregate must be one of the aggregate names from the node configuration rows. The volume is mounted at `/<volume name>`. Leave all three blank to skip the volume, the mirror refresh, and auditing. Set any of them and leave one blank and this task fails. A SnapMirror relationship is not required. | DNS domain and DNS servers | Configure cluster DNS |
| NTP servers | Configure NTP |
| Cluster name and timezone | Set the timezone. End leaves the timezone and the cluster name unchanged |
| Cluster name | Disable HTTP cluster management. This removes management-http from the default-management service policy on that cluster. End leaves HTTP removed. Leave the cluster name blank to skip this task |
| AutoSupport mail settings | Configure AutoSupport on the nodes discovered from the cluster |
| Legacy license keys or NLF contents | Add licenses. End leaves those licenses installed |
| FIPS dropdown | Set SSL FIPS mode on every launch. The dropdown defaults to `false`, which matches a new ONTAP cluster. Choose `true` to enable FIPS-compliant SSL. End sets FIPS back to false only when the dropdown is true |
| Any of SNMP contact, location, community, traphost, or SNMPv3 user | Configure and enable SNMP. Contact, location, and the SNMPv3 user each apply only when that field is filled, so leaving location or traphost blank does not skip the rest. Authentication and privacy are chosen independently, and both password fields stay on the form. With FIPS `false`, authentication is `none`, `md5`, `sha`, or `sha2_256` and privacy is `none`, `des`, or `aes128`. A password is required for each protocol that is not `none` when an SNMPv3 user is set. Community and traphost apply only when FIPS is `false` and that field is filled. With FIPS `true`, the form shows `sha` or `sha2_256` for authentication and `aes128` for privacy, and both passwords are required when an SNMPv3 user is set |
| Login banner text | Set the login banner |

## Ending the deployment

Each row shows what End does for that task. Every teardown can run again safely.

| Task | What End does |
| --- | --- |
| Update cluster location | Clears the cluster location when it still matches the form. The cluster name is not changed |
| Configure SP network | Sets the service-processor IPv4 configuration back to DHCP on each node whose address still matches the form. The static address is released, and the SP takes whatever address DHCP gives it. Disabling IPv4 is not used because ONTAP rejects it (error 13631588) on these nodes |
| Create data aggregates | Deletes the data aggregates named in the node rows after the volumes on them are gone. Root aggregates (`aggr0` and `aggr0_*`) are never deleted |
| Configure DNS | Removes cluster DNS when the DNS servers and domain still match the form |
| Configure NTP | Deletes the NTP servers named on the form that are still present |
| Configure AutoSupport | Restores the ONTAP day-0 AutoSupport defaults on the nodes where the mail hosts, from address, and to addresses still match the form. Day-0 is mail host `mailhost`, from `Postmaster`, and no to addresses. AutoSupport stays enabled. A proxy URL entered on the form is cleared |
| Configure FIPS | When the dropdown is true and the cluster still has FIPS enabled, sets SSL FIPS mode to false. When the dropdown is false, End leaves FIPS unchanged |
| Configure SNMP | Removes the SNMP community, SNMPv3 user, and traphost named on the form, and clears the contact and location when they were set |
| Create login banner | Clears the cluster login banner when it still matches the form |
| Configure interface group | Removes the member ports, then deletes the interface group with the name entered, on each node that lists data ports |
| Configure IPspace | Deletes the IPspace with the name entered. `Default` and `Cluster` are refused. ONTAP removes the empty Default broadcast domain with it |
| Configure broadcast domains | Deletes the broadcast domain for each filled-in VLAN name (in-band management, NFS, iSCSI A, and iSCSI B) |
| Configure VLAN interfaces | Deletes the VLAN interfaces for the filled-in VLAN IDs on the interface group |
| Configure SVM | Deletes the SVM and its root volume. Runs after the LIFs, export-policy rule, audit log, and load-sharing volumes are gone |
| Configure load-sharing SnapMirror | Deletes the load-sharing relationships and the mirror volumes named `<root>_lsm0<hex>`. Deletes the job schedule only when it is not a built-in schedule and no SnapMirror relationship still uses it |
| Configure vsadmin | No teardown. The password stays set until the SVM is deleted |
| SVM login banner | Clears the SVM login banner when the SVM still shows the text from the form |
| SVM management LIF | Deletes the SVM management LIF named on the form |
| SVM default route | Deletes the SVM default route |
| SVM DNS | Removes DNS from the SVM |
| NFS export policy rule | Deletes rule index 1 on the SVM default export policy. The policy stays until the SVM is deleted |
| SVM audit log | Disables SVM auditing, then deletes the audit log volume |
| NFS LIFs | Deletes the NFS LIFs |
| iSCSI LIFs | Deletes the iSCSI LIFs on fabric A and fabric B |

Pre-validation, cluster-management auto-revert, spare-disk zeroing, delete default broadcast domains, cluster HA, CDP, LLDP, storage failover, timezone, licenses, flow control, HTTP cluster management, discover disk class, and post-config validation have no teardown. Configure FIPS has a teardown only when FIPS is true.
