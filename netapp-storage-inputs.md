# Inputs for the ONTAP storage blueprint

Launch-form inputs for `blueprints/ontap-storage-setup.yaml`, in one table. The Section column is the launch form section and is filled in only on the first row of that section.

## Storage: ONTAP cluster and SVM

58 inputs: 3 must be entered (Default is none), 42 can be left blank (Default is blank allowed), and 13 are pre-filled. Two of the pre-filled values are an empty list (`[]`): the node table and the protocol dropdown. Fibre Channel, NVMe, and S3 are not included.

Only the agent, the cluster management address, and the password are required. The username defaults to `admin`. A launch can finish with just those. SSL FIPS defaults to `false` and is applied on every launch.

A blank-allowed field is optional. Where a task needs several fields, the row says what a partial fill does. Cluster DNS runs only when both the domain and the servers are set, and AutoSupport mail runs only when the mail hosts, From address, and To addresses are all set. A partial fill skips that task. SVM DNS, the audit log volume, and the job schedule fail if only part of the set is filled in. SNMP is the other way around: any one of contact, location, community, traphost, or the SNMPv3 user runs SNMP, and a blank sibling does not skip the rest.

The rows under Node configuration after `node_specs` are the columns of that one table. They are not separate blueprint inputs, so they are not in the 58. The launch form section title is: "Node configuration. One row per node and one aggregate. Fill in NFS/iSCSI LIF details based on the protocol.Skip if not needed. To skip these tasks, delete every row. A blank row keeps Finish disabled."

Some tasks run on every launch and have no field of their own: pre-validation, cluster-management auto-revert, spare-disk zeroing, default broadcast-domain cleanup, cluster HA, CDP, LLDP, and storage failover. Cluster HA is set only when discovery finds exactly two nodes.

| Section | Input | Type | Default | What to enter |
|---|---|---|---|---|
| Management Server | agent | agent | none | Torque agent that runs the steps. Select one that can reach the ONTAP cluster. |
| Cluster Details | ontap_hostname | string | none | ONTAP cluster management IP address or hostname. |
|  | ontap_username | string | `admin` | ONTAP cluster administrator username. |
|  | ontap_password | string | none | ONTAP cluster administrator password. Sensitive (hidden in logs). |
|  | cluster_name | string | blank allowed | ONTAP cluster name. Must exactly match the cluster's current name. Entering a different value renames the cluster when location or timezone is set. Used by location, timezone, and disabling HTTP cluster management. Leave blank to skip those tasks and leave HTTP management unchanged. |
|  | cluster_location | string | blank allowed | Location string stored on the cluster. Runs only when the cluster name is also set. |
|  | time_zone | string | blank allowed | ONTAP timezone name, for example America/Los_Angeles. Runs only when the cluster name is also set. |
|  | cluster_login_banner | string | blank allowed | Login banner text for the cluster. Leave blank to skip the banner. |
| Node configuration | node_specs | string | `[]` | One row per node, shown on the form as a table. The node name is entered once and applies to that node's service processor, data ports, interface group, and one aggregate. Aggregate names from these rows are assigned to the SVM when an SVM name is set. Delete every row to skip the service-processor, aggregate, interface-group, and data-port tasks. A blank row keeps Finish disabled. The columns are the rows below. |
|  | Node Name | string | blank allowed | Column of `node_specs`. ONTAP node name. Each node can appear only once. Required on any row that sets an SP address, data ports, an aggregate, or a LIF. |
|  | SP IP | string | blank allowed | Column of `node_specs`. Service-processor IPv4 address. Set this together with SP Netmask and SP Gateway, or leave all three blank to skip the service processor on that node. |
|  | SP Netmask | string | blank allowed | Column of `node_specs`. Service-processor subnet mask, in dotted decimal form. Required when SP IP or SP Gateway is set. |
|  | SP Gateway | string | blank allowed | Column of `node_specs`. Service-processor gateway. Required when SP IP or SP Netmask is set. |
|  | Data Ports | string | blank allowed | Column of `node_specs`. Comma-separated data ports added to the interface group, for example e5a,e5b. Flow control is disabled on these ports. In-band management, NFS, and iSCSI VLANs are created on the interface group of each node that lists data ports. Leave blank and that node gets no interface group, no flow-control change, and no VLAN interfaces. |
|  | Aggregate Name | string | blank allowed | Column of `node_specs`. Name of the one data aggregate created on this node. Set this together with Disk Count. Disk class is discovered when an aggregate name or a disk count is set. These names are assigned to the SVM when an SVM name is set. |
|  | Disk Count | string | blank allowed | Column of `node_specs`. Number of disks in that aggregate. Whole number above zero. Required when Aggregate Name is set. |
|  | NFS LIF Name | string | blank allowed | Column of `node_specs`. NFS data LIF name on this node. Required on every row when nfs is selected, the SVM name is set, and the NFS VLAN ID is set. Each name can appear only once. |
|  | NFS LIF Address | string | blank allowed | Column of `node_specs`. IPv4 address of the NFS data LIF. Required together with NFS LIF Name and NFS LIF Netmask. |
|  | NFS LIF Netmask | string | blank allowed | Column of `node_specs`. Subnet mask of the NFS data LIF, in dotted decimal form. The home port is the NFS VLAN interface, for example a0a-3052. |
|  | iSCSI A LIF Name | string | blank allowed | Column of `node_specs`. iSCSI data LIF name on fabric A. Required on every row when iscsi is selected, the SVM name is set, and both iSCSI VLAN IDs are set. Each A and B name, across all nodes, must be unique. |
|  | iSCSI A LIF Address | string | blank allowed | Column of `node_specs`. IPv4 address of the fabric A iSCSI LIF. |
|  | iSCSI A LIF Netmask | string | blank allowed | Column of `node_specs`. Subnet mask of the fabric A iSCSI LIF, in dotted decimal form. The home port is the fabric A VLAN interface, for example a0a-3012. |
|  | iSCSI B LIF Name | string | blank allowed | Column of `node_specs`. iSCSI data LIF name on fabric B. Required together with the other iSCSI A and B columns when iSCSI LIFs are created. |
|  | iSCSI B LIF Address | string | blank allowed | Column of `node_specs`. IPv4 address of the fabric B iSCSI LIF. |
|  | iSCSI B LIF Netmask | string | blank allowed | Column of `node_specs`. Subnet mask of the fabric B iSCSI LIF, in dotted decimal form. The home port is the fabric B VLAN interface, for example a0a-3022. |
| DNS and NTP | dns_domain_name | string | blank allowed | Cluster DNS domain name. Both this and the DNS servers are required to configure cluster DNS. Separate from SVM DNS. |
|  | dns_servers | string | blank allowed | Comma-separated cluster DNS server IP addresses. Both this and the DNS domain are required. |
|  | ntp_servers | string | blank allowed | Comma-separated NTP server IP addresses. Leave blank to skip NTP. |
| AutoSupport Parameters | autosupport_mail_hosts | string | blank allowed | Comma-separated AutoSupport mail hosts. Mail hosts, the From address, and the To addresses are all required to configure AutoSupport. |
|  | autosupport_from_address | string | blank allowed | AutoSupport From address. |
|  | autosupport_to_addresses | string | blank allowed | Comma-separated AutoSupport recipient addresses. |
|  | autosupport_proxy_url | string | blank allowed | Optional AutoSupport proxy URL. Leave empty to omit it. Applied only when the mail settings are filled in. |
|  | autosupport_message | string | `FlexPod ONTAP Storage Configuration completed` | Text of the AutoSupport test sent at the end of post-config validation. That validation runs when this field is filled in. Clear it and the validation is skipped. |
| ONTAP Licenses | legacy_license_keys | string | blank allowed | Comma-separated legacy license keys. Either this or the NLF contents adds licenses. Sensitive (hidden in logs). Leave both blank to skip. |
|  | nlf_license_content | string | blank allowed | Full contents of the NetApp license file (NLF). Sensitive (hidden in logs). |
| FIPS and SNMP Configuration Parameters | is_fips_enabled | string | `false` | SSL FIPS mode. Dropdown: `false` or `true`. Defaults to false, which matches a new ONTAP cluster. Choose true to enable FIPS-compliant SSL. Every launch applies this value. When true, the form hides community, traphost, and the non-FIPS protocol dropdowns, and shows the FIPS protocol dropdowns. |
|  | snmp_contact | string | blank allowed | Optional SNMP contact string. SNMP runs when any of contact, location, community, traphost, or the SNMPv3 user is set. Leaving one of them blank does not skip the others. |
|  | snmp_location | string | blank allowed | Optional SNMP location string. Applied only when this field is filled in. |
|  | traphost_ip | string | blank allowed | Optional SNMP trap host. Shown only when FIPS is not enabled. Applied only when FIPS is false and this field is filled in. |
|  | snmp_community | string | blank allowed | Optional SNMPv1/v2c community name. Shown only when FIPS is not enabled. Applied only when FIPS is false and this field is filled in. |
|  | snmp_v3_user | string | blank allowed | Optional SNMPv3 user name. Leave blank to skip SNMPv3. |
|  | snmp_auth_protocol | string | `none` | SNMPv3 authentication protocol when FIPS is off. Dropdown: `none`, `md5`, `sha`, `sha2_256`. Shown only when FIPS is not enabled. A password is required unless this is `none`, and only when an SNMPv3 user is set. |
|  | snmp_auth_protocol_fips | string | `sha` | SNMPv3 authentication protocol when FIPS is on. Dropdown: `sha`, `sha2_256`. Shown only when FIPS is enabled. The password is required when an SNMPv3 user is set. |
|  | snmp_auth_password | string | blank allowed | SNMPv3 authentication password. Sensitive (hidden in logs). Required when the authentication protocol is not `none` and an SNMPv3 user is set. With FIPS on, required whenever an SNMPv3 user is set. |
|  | snmp_priv_protocol | string | `none` | SNMPv3 privacy protocol when FIPS is off. Dropdown: `none`, `des`, `aes128`. Shown only when FIPS is not enabled. A password is required unless this is `none`, and only when an SNMPv3 user is set. |
|  | snmp_priv_protocol_fips | string | `aes128` | SNMPv3 privacy protocol when FIPS is on. Dropdown: `aes128` only. Shown only when FIPS is enabled. The password is required when an SNMPv3 user is set. |
|  | snmp_priv_password | string | blank allowed | SNMPv3 privacy password. Sensitive (hidden in logs). Required when the privacy protocol is not `none` and an SNMPv3 user is set. With FIPS on, required whenever an SNMPv3 user is set. |
| Network Configuration | ifgrp_name | string | `a0a` | Interface group created on every node that lists data ports. Use a name such as a0a or a0b: the letter a, a number from 0 to 999 with no leading zeros, and one lowercase letter. Traffic is distributed by port and the group MTU is 9000. Clear this field to skip only the interface group. In-band management, NFS, and iSCSI VLANs are created on this group when those VLANs are filled in. |
|  | ifgrp_mode | string | `multimode_lacp` | Interface group mode. Dropdown: `multimode_lacp`, `multimode`, `singlemode`. multimode_lacp bundles the member ports with LACP, multimode bundles them without LACP, and singlemode keeps one port active and uses the others for failover. Applied when the group is created. |
|  | ipspace_name | string | blank allowed | IPspace for the in-band management, NFS, and iSCSI broadcast domains and VLANs. Example: AA02-OCP. The name starts with a letter or underscore. The SVM is created in this IPspace when an SVM name is set. Leave blank to skip IPspace, broadcast domain, and VLAN creation. The interface group task does not read this field. |
|  | ib_mgmt_vlan_name | string | blank allowed | In-band management VLAN name. This name is also the broadcast domain name. Example: OCP-BareMetal-MGMT. Broadcast domain MTU is 1500. Leave blank to skip that broadcast domain. The VLAN ID is used only for the VLAN interface. Requires the IPspace name. |
|  | ib_mgmt_vlan_id | string | blank allowed | In-band management VLAN ID, from 1 to 4094. Example: 1022. ONTAP names the interface `<interface group>-<VLAN ID>`, for example a0a-1022. Leave blank to skip the VLAN interface. The broadcast domain is still created when the VLAN name is set. |
|  | nfs_vlan_name | string | blank allowed | NFS VLAN name. This name is also the broadcast domain name. Example: OCP-NFS. Broadcast domain MTU is 9000. Leave blank to skip the NFS broadcast domain. Requires the IPspace name. |
|  | nfs_vlan_id | string | blank allowed | NFS VLAN ID, from 1 to 4094. Example: 3052. Leave blank to skip the NFS VLAN interface and the NFS data LIFs. The broadcast domain is still created when the VLAN name is set. |
|  | iscsi_a_vlan_name | string | blank allowed | iSCSI VLAN name for fabric A. This name is also the broadcast domain name. Example: OCP-iSCSI-A. Broadcast domain MTU is 9000. Leave blank to skip the fabric A broadcast domain. Requires the IPspace name. |
|  | iscsi_a_vlan_id | string | blank allowed | iSCSI VLAN ID for fabric A, from 1 to 4094. Example: 3012. Leave blank to skip the fabric A VLAN interface. Both fabric A and fabric B VLAN IDs are required for the iSCSI data LIFs. |
|  | iscsi_b_vlan_name | string | blank allowed | iSCSI VLAN name for fabric B. This name is also the broadcast domain name. Example: OCP-iSCSI-B. Broadcast domain MTU is 9000. Leave blank to skip the fabric B broadcast domain. Requires the IPspace name. |
|  | iscsi_b_vlan_id | string | blank allowed | iSCSI VLAN ID for fabric B, from 1 to 4094. Example: 3022. Leave blank to skip the fabric B VLAN interface. The broadcast domain is still created when the VLAN name is set. |
| SVM Configuration | svm_name | string | blank allowed | SVM name. Example: AA02-OCP-SVM. The name starts with a letter or underscore. The SVM is created in the IPspace from Network Configuration, and the aggregate names from the node rows are assigned to it. Leave blank to skip SVM creation and everything that follows it: protocols, load-sharing SnapMirror, vsadmin, the SVM banner, the management LIF, the default route, SVM DNS, the NFS export policy, the audit log volume, and the NFS and iSCSI data LIFs. |
|  | allowed_protocols | string | `[]` | Protocols allowed on the SVM. Multi-select. The dropdown starts empty. Choose `nfs`, `iscsi`, or both. At least one is required when the SVM name is set. The selected license must already be installed, and every serial for that package must be compliant. nfs starts NFSv3 and NFSv4.1 and disables UDP. iscsi starts the iSCSI service. |
|  | job_name | string | `15min` | Job schedule name for the load-sharing SnapMirror of the SVM root volume. The name starts with a letter, number, or underscore. Both this and the job minutes are required. Both are pre-filled, so an SVM name alone also creates this schedule unless both fields are cleared. Set only one and the task fails at the schedule, after the SVM is already created. |
|  | job_minutes | string | `0,15,30,45` | Minutes of each hour when the job schedule runs, separated by commas. Each value is a whole number from 0 to 59. The default runs at minute 0, 15, 30, and 45. Other 15-minute examples are 5,20,35,50 and 7,22,37,52. Clear both this and the job name to skip the load-sharing SnapMirror. |
|  | vsadmin_password | string | blank allowed | Password for the SVM vsadmin account. Sensitive (hidden in logs). When filled in, the password is set and vsadmin is unlocked for http, ontapi, and ssh. Leave blank to leave vsadmin unchanged. Requires the SVM name. |
|  | svm_login_banner | string | blank allowed | Login banner text for the SVM. Leave blank to skip the SVM banner. Requires the SVM name. |
|  | svm_mgmt_lif_name | string | blank allowed | Name of the SVM management LIF. One SVM has one management LIF. Example: svm-mgmt. The name starts with a letter or underscore. Fill this in together with the address and netmask. Also requires the interface group name, the in-band management VLAN name and VLAN ID, the SVM name, and data ports on at least one node row. The home port is `<interface group>-<VLAN ID>`, for example a0a-1022. Service policy default-management, failover policy broadcast-domain-wide, auto-revert enabled. Leave any of the three LIF fields blank to skip the LIF and the default route. |
|  | svm_mgmt_lif_address | string | blank allowed | IPv4 address of the SVM management LIF. Example: 10.102.2.50. |
|  | svm_mgmt_lif_netmask | string | blank allowed | Subnet mask of the SVM management LIF, in dotted decimal form. Example: 255.255.255.0. |
|  | svm_mgmt_lif_gateway | string | blank allowed | IPv4 gateway for the SVM management LIF. Example: 10.102.2.254. Becomes the SVM default route to 0.0.0.0/0. Must be different from the LIF address. Leave blank to skip the route. The LIF can still be created without it. If the LIF is skipped, the route is skipped as well. |
|  | svm_dns_servers | string | blank allowed | Comma-separated DNS server IPv4 addresses for the SVM. Example: 10.1.1.10,10.1.1.11. Separate from the cluster DNS servers. Fill this in together with the SVM DNS domain. Leave both blank to skip SVM DNS. Set only one and the SVM DNS task fails. Requires the SVM name. |
|  | svm_dns_domain | string | blank allowed | DNS domain name for the SVM. Example: example.com. Separate from the cluster DNS domain. Fill this in together with the SVM DNS servers. |
| Volume Configuration | nfs_client_match | string | blank allowed | IPv4 subnet for rule index 1 on the SVM default export policy. Example: 192.168.52.0/24. Protocol is nfs. Read-only, read-write, and superuser security are sys, and suid is allowed. The same policy is then assigned to the SVM root volume. nfs must be selected. Leave blank to skip the rule and that assignment. Requires the SVM name. |
|  | audit_log_volume_name | string | blank allowed | Name of the FlexVol that stores the SVM audit logs. Example: audit_log. The name starts with a letter or underscore and contains only letters, numbers, and underscores. The volume is mounted at `/<volume name>`. All three audit fields are required together. Leave all three blank to skip the volume and auditing. Set any of them and leave one blank and the task fails. Requires the SVM name. |
|  | audit_log_volume_size_gb | string | blank allowed | Size of the audit log FlexVol in gigabytes. Enter the number only. Example: 50. Whole number from 1 to 9999999. The volume is online, uses export policy default, has no space guarantee, and has no snapshot reserve. |
|  | audit_log_aggregate | string | blank allowed | Aggregate that holds the audit log FlexVol. Example: AA02_C800_01_SSD_CAP_1. Use an aggregate name from the node configuration rows. |
